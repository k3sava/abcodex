# When AI automates code generation at scale, human code review becomes the primary throughput constraint

## Claim
Once a software factory automates code generation, the bottleneck moves from producing code to reviewing it. Human attention for code review is the scarce resource that limits how many PRs the organization can merge.

## Mechanism
Code generation is now cheap and fast. A factory that generates 2,000 PRs per month does not struggle to produce code. It struggles to get engineers to review 2,000 PRs. The review step requires human judgment: understanding intent, evaluating correctness across complex codebases, and catching subtle errors that test suites miss. This is not a step that can be easily automated without accepting higher defect rates. As generation throughput rises, the review queue is the first thing that backs up.

The implication for engineering organization is direct: optimizing for code generation speed has diminishing returns once the factory is running. Optimizing for review throughput, through better tooling, tighter scoping, or more reviewers, becomes the next constraint worth solving.

## Conditions
Holds when: the organization has built or adopted a software factory that automates code generation at meaningful volume. Before that point, generation speed is the constraint.

Fails when: the code generated by the factory is low-trust and requires full re-read by reviewers on every PR, eliminating the speed advantage. Review remains the bottleneck in that case too, but for a different reason: quality problems, not throughput.

## Evidence
Zach Lloyd described this dynamic on the "How I AI" podcast for Lenny Rachitsky on September 21, 2026. With Warp's Wilson agent merging 2,000 PRs monthly, Lloyd identified human code review as the main organizational constraint. He measures this by tracking human interactions per PR as a signal of automation quality, using the metric to understand where engineer time concentrates. The organization's bottleneck is no longer writing code.

## Signals
- The PR merge rate plateaus while the PR generation rate continues to grow.
- Senior engineer time concentrates increasingly in the review queue.
- Teams debate adding reviewers or increasing reviewer throughput rather than adding more code-writing agents.

## Counter-evidence
Some AI-native teams report that well-scoped, highly-tested agent output requires less review time per PR than human-written code of equivalent scope. If the factory produces narrow, fully-tested PRs with high confidence, review overhead can remain low even at high volume. The bottleneck shifts back toward generation if scoping discipline holds.
