# What landed today

Four new cards today, one new operator. Steve Yegge published "The Shape of Things to Come" this week, writing from the perspective of someone actually running hundreds of parallel coding agents right now. Harrison Chase's team released Managed Deep Agents into public beta on August 7. Two practitioner angles on the same underlying problem: agent-scale engineering requires infrastructure that does not yet exist as standard tooling.

## Theme 1, CI/CD and harnesses break at agent scale

Steve Yegge's Part 1 essay is an account of the engineering problems that emerge when a team moves from a few coding agents to hundreds running in parallel. The first problem is the merge queue. Traditional CI/CD pipelines assume one PR at a time; at agent scale, the queue backlog grows faster than commits can land. Yegge argues this requires a fundamental model change: simultaneous commit landing with batch failure analysis, which he calls "Thunderdome." `ins_yegge-thunderdome-cicd` documents this pattern and its preconditions.

The second problem is harness brittleness. Yegge's Gas Town framework broke when an upstream model upgrade introduced new behavioral patterns his harness had not anticipated. His conclusion: harnesses must be built into the application as native infrastructure, not external layers. `ins_yegge-harness-model-coupling` captures the specific failure mode and his proposed fix. Both cards draw from the same essay.

- Steve Yegge, `ins_yegge-thunderdome-cicd`. Serial CI/CD merge queues cannot drain when hundreds of coding agents are running in parallel; simultaneous landing with swarm failure analysis is needed.
- Steve Yegge, `ins_yegge-harness-model-coupling`. Agent harnesses built around one model version break when the model upgrades; harnesses need to be native application infrastructure, not external wrappers.

## Theme 2, Agent identity and infrastructure as engineering problems

Yegge's Part 2 addresses the agent identity question. Named persistent agent roles with continuity across model upgrades, what he calls "seats," produce better engineering outputs than stateless sessions. He draws on research about purpose and continuity in human work to argue the same principles apply to AI agents: bounded workdays, role specialization, and consent-based handoff between model versions. `ins_yegge-seats-not-sessions` documents this.

Harrison Chase's team approaches the same underlying substrate problem from the platform side. Their Managed Deep Agents release packages durable execution, memory persistence, sandboxing, and deployment into a shared runtime. The observation behind the product is that teams building production agents spend most of their time rebuilding identical infrastructure before they can work on agent-specific logic. `ins_chase-agent-infra-rebuild-tax` captures this diagnosis. It connects to Chase's earlier work on compounding intelligence (`ins_chase-compound-intelligence-ownership`), though the specific claim here is about infrastructure cost rather than capability ownership.

- Steve Yegge, `ins_yegge-seats-not-sessions`. Named persistent agent roles with continuity across model upgrades produce better outcomes than stateless session pools.
- Harrison Chase, `ins_chase-agent-infra-rebuild-tax`. Rebuilding durable execution, persistence, and sandboxing per project is the primary cost in production agent development, not AI capability itself.
