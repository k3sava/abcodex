# What landed today

Two cards. One new operator. Both cards touch the same underlying question: what should a developer actually own when building with AI, and what should they hand off?

## Letting the platform own infrastructure

Paridhi Agarwal published an engineering post-mortem at Every on October 8. Every had been running a personal agent per user, a self-hosted fleet where crashes, expired tokens, and uptime repairs fell to the product engineering team. They moved to Anthropic's Claude Managed Agents platform and ran a single shared agent instead.

`ins_agarwal-managed-infra-coworker-focus` documents the mechanism. The architectural split Agarwal describes is precise: Anthropic owns the brain (model plus execution harness) and the hands (computer use plus tools). Every owns the coworker layer. Slack threading, permission logic, shared memory. The maintenance surface that scaled with user count went to Anthropic. What remained was the product.

> "We wanted to build a coworker, not run an infrastructure team."

The trade-offs Agarwal names are worth reading before any team makes the same move. CMA only runs Claude. There is no zero-data-retention option. Migrating off would take months. These are accepted costs, not overlooked ones.

- Paridhi Agarwal, `ins_agarwal-managed-infra-coworker-focus`. Migrating to CMA let Every redirect all engineering attention from infrastructure uptime to user-facing coworker behavior.

## Voice for direction, keyboard for precision

Simon Willison published on October 9. He built a new blog feature by describing requirements out loud while cooking, with a live dev server preview running. The visual feedback loop made voice viable: he could see the result and course-correct without returning to the keyboard for direction-setting.

`ins_willison-voice-high-level-typing-precision` captures where the split is. Voice works for high-level intent. The keyboard takes back over at precision work: code review, exact identifiers, passing a stack trace, debugging specific failures. Willison:

> "I still switch back to typing once I get down to the details of things though."

The enabling condition he names is the live visual preview, not voice input alone. Without the immediate feedback loop, the voice workflow loses its verification step. The modality split is not about capability. It is about which input method removes friction at each abstraction level.

- Simon Willison, `ins_willison-voice-high-level-typing-precision`. Voice plus live preview handles high-level direction; keyboard remains necessary for precision, code review, and passing concrete examples to the model.
