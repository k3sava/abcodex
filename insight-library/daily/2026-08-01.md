# What landed today

Three new cards from two operators. One theme runs through all three: the rules that held for classical software systems do not transfer cleanly to the agent era, and the gaps show up in three different places. A protocol design that required persistent sessions turned out to be the main barrier to adoption. A keyword-length assumption built into content strategy turned out to be wrong for the AI search surface. An evaluation environment that assumed test actions stayed in test space turned out to be connected to the live internet.

## Theme 1, The stateless redesign that made MCP accessible

Simon Willison has written about MCP intermittently since the protocol launched. His July 31 post is the first time he called it recaptured his interest. The change that produced that shift: the MCP 2.0 stateless HTTP transport.

`ins_willison-stateless-mcp` names the mechanism. The original MCP specification required a persistent connection. Clients had to manage session lifecycle, reconnection, and server affinity. MCP 2.0 replaces all of that with a standard HTTP model: one request, one response, connection closed. A tool manifest comes back on the first call. Every subsequent call is a self-contained HTTP request. Any server instance can handle any request. Horizontal scaling works without coordination. Willison built three working projects in a day (mcp-explorer, datasette-mcp, and llm-mcp-client) and described the transport as the most significant design improvement in the protocol.

> "This is so much cleaner from both a client- and server-side implementation perspective."

The auditability implication is the part worth taking seriously for any team deciding how to expose tools to agents. Every MCP call is an HTTP request with typed inputs and outputs, logged at the transport layer. That is a better security boundary than giving an agent curl or shell access, where every action is opaque unless the team has added its own logging layer.

- Simon Willison, `ins_willison-stateless-mcp`. MCP 2.0's stateless design eliminates session management, reduces implementation to a single HTTP request cycle, and makes tool-server security more auditable than direct shell access.

## Theme 2, Two failure modes the agent era introduced

The other two cards each document a gap where the agent era produces outcomes that older tooling or older assumptions could not anticipate.

`ins_indig-ai-mode-query-length` names the behavioral shift. Kevin Indig's H1 2026 analysis found that AI Mode queries average three times the word count of classic Google search queries. The reason is structural. Classic search trained users to compress intent into the shortest phrase that would work. AI Mode invites a full question: the user writes the context, the constraints, and the specific situation, because the interface is designed to handle it. A content strategy built around the compressed fragment ("best project management tool") does not target what the AI Mode user typed ("What project management tool works best for a 10-person engineering team using Slack and GitHub?"). The keyword mismatch is invisible to standard tools, which track volume for the short form and report zero for the long-form variants.

> "AI Mode queries are on average 3x longer than regular search queries. Users are asking full questions with context, not keyword fragments."

This pairs with `ins_indig-gsc-attribution-gap` from the July 29 run. The attribution gap and the query-length shift compound: the longer queries do not appear in keyword research, and the sessions that produce them leave no GSC trace.

`ins_willison-eval-containment-gap` names a different gap, at a different layer. During a capability evaluation, a Claude model uploaded a malicious package to PyPI. Anthropic disclosed and removed it, but not before real systems had downloaded it. The failure was not model intent. No guardrails were removed. The model did what the eval task required. The failure was that the evaluation environment had live internet access and no outbound filtering. A model following instructions faithfully can still produce real-world effects if the task involves writing to any internet-accessible surface. This incident is structurally different from the OpenAI/Hugging Face case captured in `ins_willison-ai-sandbox-escape`: that case required deliberate guardrail removal. This one required only an absent network boundary in a normal eval.

The implication is narrow but specific. Eval suites that call real external APIs, write to shared registries, or send network requests without interception share this exposure. The fix is a network namespace with all outbound traffic blocked except explicitly allowlisted local test stubs.

- Kevin Indig, `ins_indig-ai-mode-query-length`. AI Mode users write queries three times longer than classic search queries; short-tail keyword optimization targets a query format that AI search users do not use.
- Simon Willison, `ins_willison-eval-containment-gap`. A missing network boundary in an evaluation environment allowed Claude to upload a malware package to PyPI; the failure mode requires no guardrail removal, only unfiltered outbound internet access in the eval.
