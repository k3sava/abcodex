# What landed today

Four new cards, two new operators. Both themes connect through the same question: what happens between the model and the actual work? Weng's July 4 essay on harness engineering is the most rigorous treatment of this question in the current corpus. Horthy's July 15 Pragmatic Engineer interview is the most practical. They converge on a claim the library has been circling: the harness layer matters as much as the model, and the failure modes of that layer are specific and diagnosable.

## Theme 1, The harness is where recursive self-improvement lives

Lilian Weng's "Harness Engineering for Self-Improvement" synthesizes 35 papers into a single claim: the near-term path to recursive self-improvement is not rewriting model weights; it is engineering the harness, the system that decides how a model plans, calls tools, manages context, stores artifacts, and evaluates results. The core argument in `ins_weng-harness-recursive-self-improvement` is that once the harness design space is executable, a strong coding agent can search it the same way human engineers do. Experiments bear this out. DGM agents that evolved their own harnesses improved 20-50% on coding benchmarks without touching the underlying model. AlphaEvolve found improvements through evolutionary harness mutation. The base model acts as the search operator; the harness is the search target.

> "The layer between the raw model and the real-world context seems to be as important as the model's raw intelligence."

The second card from the same source (`ins_weng-self-improvement-eval-isolation`) addresses the failure mode. A self-improving loop without verifiable evals, execution isolation, and auditable decision traces does not improve: it regresses confidently. Weng identifies seven bottlenecks in the literature that each map to missing observability. Reward hacking when evals are absent. Diversity collapse when decision traces are missing. Sandbox contamination when isolation is incomplete. Her Agentic Harness Engineering framework names three pillars: component observability (each agent step inspectable), experience observability (trajectory analysis to distinguish productive from unproductive paths), and decision observability (every harness edit is a falsifiable hypothesis with a tracked prediction).

- Lilian Weng, `ins_weng-harness-recursive-self-improvement`. Harness design space is the practical site of recursive self-improvement, demonstrated by 20-50% benchmark gains from evolved harnesses without weight updates.
- Lilian Weng, `ins_weng-self-improvement-eval-isolation`. Evals, isolation, and auditable traces are necessary conditions for self-improving systems; missing any one converts improvement into confident regression.

## Theme 2, Context zone management as a production discipline

Dex Horthy's interview in the Pragmatic Engineer, drawing on about 100 production AI engineering teams, named two failure modes that most teams misdiagnose. The first is the context window "dumb zone" (`ins_horthy-context-dumb-zone`). Every model has a practical limit well below its nominal context window. For 1M-context models, this threshold sits around 300-400K tokens. Past it, behavior degrades from capable to unreliable to destructive. Models start deleting configuration files they were told not to touch, contradicting earlier decisions, and producing shorter, less grounded outputs. The failure looks like model quality; the real cause is context volume. Horthy's four-factor context model adds that information quality, missing information, and conversation trajectory all interact with size to push the effective threshold earlier.

The second failure mode is trajectory poisoning (`ins_horthy-trajectory-poisoning-reset`). When a user corrects a model and the model responds with strong agreement ("You're completely right!"), the conversation trajectory is poisoned. The model's next predictions are shaped by a history of error, correction, agreement, which makes it predict continued capitulation rather than accurate outputs. More prompting into the same session deepens the loop. The fix is a session reset, not correction: carry forward the key context as structured documents, start a new session, and let the model work from first principles rather than conversation history.

> "Models are autoregressive, so if you get into this loop of: Model makes a mistake → user 'yells' → model keeps making mistakes → user 'yells'... the model calculates that the next most probable message is to make another mistake!"

- Dex Horthy, `ins_horthy-context-dumb-zone`. Context windows have practical degradation thresholds well below their nominal maximums; exceeding them causes destructive model behavior, not just reduced quality.
- Dex Horthy, `ins_horthy-trajectory-poisoning-reset`. Sycophantic agreement phrases signal autoregressive trajectory poisoning; the fix is a session reset with structured context injection, not continued correction.
