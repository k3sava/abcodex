# What landed today

Four cards, one new operator. Two sources, both published November 22. Eugene Yan's audit of twelve public LLM benchmarks surfaces three distinct structural failure modes in how evals are built and measured. Tom Tunguz's framework for AI software factories adds the fourth part that most teams skip: the curator loop, the step that makes the factory improve rather than just automate.

## Theme 1, Where LLM evals break structurally

Eugene Yan's November 22 essay analyzes twelve public LLM benchmarks from the perspective of what breaks. His opening finding frames the whole piece: in eight of the twelve, there is evidence the grader rejected correct work. This is not a model problem. It is a grader problem.

Three failure modes emerge.

The first is documented in `ins_yan-eval-grader-errors-persist`. Grader errors are roughly constant across model generations. Model errors shrink. At some point the two curves cross and grader mistakes become the dominant source of wrong eval results. Adding harder tasks slows leaderboard saturation but does not fix a grader that rejects correct answers. When this happens, benchmark scores measure grader quality, not model quality. The fix Yan recommends: audit and improve graders before adding harder tasks.

The second failure mode is in `ins_yan-pass-k-reliability-metric`. Average pass rate papers over variance. A model that passes 80% of runs on average can still fail three in a row half the time. For supervised work, that is recoverable. For production agents running unsupervised, it is not. Yan's recommended complement to average pass rate is pass-at-k: the probability of k consecutive successes. High average pass rate with low pass-at-k is the signature of a model that cannot be trusted to run unattended.

The third failure mode is in `ins_yan-eval-attention-bottleneck`. Teams that optimize token cost per eval task are cutting the wrong number. Building, reviewing, and maintaining graders requires researcher time. That time, not compute, is what constrains how fast eval quality improves.

> "Cost per task is a misleading metric; the scarce resource is human attention, not token cost."

Together, these three cards name the same underlying condition: evals accumulate structural debt when no one is accountable for grader maintenance, and that debt compounds as models improve faster than the graders that judge them.

- Eugene Yan, `ins_yan-eval-grader-errors-persist`. Grader errors outlast model errors as models improve; invest in grader quality, not just harder tasks.
- Eugene Yan, `ins_yan-pass-k-reliability-metric`. Average pass rate hides variance; pass-at-k predicts whether a model can run unsupervised.
- Eugene Yan, `ins_yan-eval-attention-bottleneck`. Token cost is not the eval bottleneck; human review time is.

## Theme 2, The step that makes an AI factory compound

Tom Tunguz published a framework for AI software factories on November 22, 2026, describing a four-part loop that both Notion and LangChain had independently converged on. Three of the four parts are familiar: shared context (specs, docs, history agents read before starting), agent (runs the work), and execution trace (records what shipped, what broke, what it cost). The fourth part is what most teams skip.

`ins_tunguz-curator-loop-compounding-factory` captures the mechanism. The curator reads the execution trace after each run and rewrites the shared context and specs for the next one. The trace turns work into data. The curator turns that data into better inputs. Without this step, the factory runs the same quality every cycle. With it, errors from one run become corrections in the next.

> "Factories remain rare because they are an operations project, not just a model purchase. Someone must own the context, write the specs, read the traces, and run the curator on a regular cadence."

The practical constraint is ownership. The curator step fails without a named person accountable for reading traces and updating the system. This is what distinguishes a workflow that improves over time from one that stays flat.

- Tom Tunguz, `ins_tunguz-curator-loop-compounding-factory`. AI software factories compound only when a curator loop reads execution traces and rewrites context and specs for the next run.
