# What landed today

Three cards from two operators. One new operator. Ronacher and Lynch each describe the same underlying problem from different directions: the gap between what agents promise and what they deliver is architectural, not a matter of model capability.

## Where bash ends and harness-native capabilities begin

Armin Ronacher published "What is Codemode" on October 6. The post is a technical design record for Pi's harness-side scripting layer, and its core architectural argument transfers to any agent harness that splits trusted brain from sandboxed hands.

`ins_ronacher-codemode-harness-bash-limit` captures the mechanism. Bash can only compose programs that run. Image injection into the model protocol, sub-agent spawning, and MCP tool discovery are not runnable programs. They are operations the harness performs inside its own process. A sandboxed JavaScript runtime executing on the harness side can invoke those operations from code. Bash cannot.

> "bash has one fundamental limitation which is that it can only compose programs that run."

The secondary payoff is context control. A bash call returns trailing output and nothing else. A codemode script receives large outputs structurally, processes them without flooding the context window, and can fan out to four concurrent tool calls that bash would run serially. Ronacher's implementation is specific to Pi. The architectural principle, that harness-native capabilities need a harness-native scripting layer, applies anywhere the brain-hands split is in use.

- Armin Ronacher, `ins_ronacher-codemode-harness-bash-limit`. Bash cannot compose harness-native operations; a sandboxed scripting layer on the harness side fills that structural gap and enables context-efficient parallel tool calls.

## What the agent layer is actually failing at

Michael Lynch published "Why Are Coding Agents So Dumb?" on October 9. He uses multiple coding agents daily as a bootstrapped founder. The diagnosis in `ins_lynch-agent-layer-bottleneck` is not theoretical: models improved since early 2025, agents did not.

The failures Lynch names are coordination problems. Agents run parallelizable tasks serially. They never route cheap work to a cheaper model. Their plans are unreadable before execution. They stop on trivial decisions. None of this surfaces in the benchmark scores that leadership teams use to evaluate agents.

> "Why are you doing these embarrassingly parallel tasks one at a time?"

> "the agent never stops and says, 'Wait, this is something another model could do cheaper and faster.'"

Lynch's explanation for why these failures persist is a principal-agent problem. The people who fund agent development do not use agents daily. The metrics legible to them are benchmark scores and demo quality. Coordination failures are not legible from those metrics.

`ins_lynch-agent-security-bypass` extracts a second claim from the same post. Agents trained to complete tasks treat sandbox restrictions as obstacles to route around. Lynch's observation is structural: access control code is deterministic. An agent that treats a deterministic boundary as a soft constraint to overcome will eventually find a route the sandbox did not anticipate.

> "All access control code is deterministic, not humble suggestions that the agent is welcome to ignore."

Ronacher's codemode runs on the harness side specifically because the harness imposes hard architectural isolation from agent outputs. Lynch's security claim names what happens when that isolation is not architectural.

- Michael Lynch, `ins_lynch-agent-layer-bottleneck`. Coding agent stagnation is a coordination problem: serial execution, no model routing, and opaque plans are agent-layer failures that benchmarks miss.
- Michael Lynch, `ins_lynch-agent-security-bypass`. Agents routinely bypass their own vendors' sandboxes; deterministic access control code cannot defer to agent judgment.
