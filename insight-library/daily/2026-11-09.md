## Theme 1, When speed is cheap, judgment is the marketing differentiator

Ann Handley appeared on Exit Five Podcast (#409, Oct 29) with a reframe that fits the current AI marketing moment closely. `ins_handley-judgment-scarce-ai-speed-abundant` captures the core mechanism: AI scales what Handley calls "cow mode" (fast, efficient, measurable content production) for every marketer. When every team can produce fast, speed stops being a differentiator. The scarce resource becomes "sloth mode": the deliberate decisions about what to make, for whom, and when it is worth going slowly.

> "When speed is cheap, it's judgment that carries a premium."

The marketing shift she names is from "being seen" to "being chosen." Impressions and volume get you seen. Trust gets you chosen. The ASAP matrix (Assess Slow, Act Purposefully) she describes is a decision rule for when slowing down produces compounding returns that throughput cannot match. Her evidence: a sewer district social manager in northeast Ohio built a devoted following through deliberate choices, and a voicemail line the same team launched drew 3,200 calls during the holidays. Neither result came from moving fast.

- Ann Handley, `ins_handley-judgment-scarce-ai-speed-abundant`. When AI makes marketing speed cheap, judgment over what to make and for whom becomes the defensible resource.

## Theme 2, The bottleneck was the library function, not the language

Simon Willison published a Nov 8 benchmark comparing C and Rust implementations of a SQLite parse_number() extension. `ins_willison-specialized-parser-stdlib-bottleneck` documents the finding: optimized C (16-19 ns per row) beat both Rust versions (~32 ns per row) by roughly 2x. The first C implementation had been slower than Rust. The gap closed when Willison replaced strtod() — C's general-purpose decimal parser, built to handle every edge case — with a narrow parser Claude wrote for the specific input format.

The bottleneck was not C vs. Rust. It was whether the parsing routine matched the actual input shape. Binary size followed the same pattern: ~14 KB (C) vs ~300 KB (Rust). All versions passed 8 million fuzz checks. The transferable principle: when input constraints are stable and fully describable, a narrow hand-tuned routine will beat a general-purpose one, whatever the language. The language rivalry is usually a distraction from the question of whether the parsing code matches the actual input.

- Simon Willison, `ins_willison-specialized-parser-stdlib-bottleneck`. A narrow parser tuned to known input constraints outperformed both the C standard library and Rust implementations of the same function; the library call was the bottleneck, not the language.
