## Inference without generation

llama.cpp added a structurally different inference mode in October. Decision models skip text generation entirely. The ggml-org team published the mechanism on October 2, and `ins_gerganov-decision-models-llamacpp` captures it.

A chat model generates output one token at a time. Each token extends the sequence, the output must be parsed to extract a structured answer, and the model can produce values outside the option set you intended. A decision model reads the full input in a single forward pass and computes a probability distribution directly over the options you supply. The output is always one of your options, with a confidence attached. No parsing step. No output variation across identical queries.

The ggml-org team shipped this as a new `/v1/systemone` endpoint in llama.cpp's server, with three question types: `choice` (pick one from a supplied list), `score` (expected value on an ordered 2-10 scale), and `noul` (yes/no probability). Six decision models were released, from Julia-1 at 144M parameters and 3ms median latency on an NVIDIA RTX PRO 6000, through OpenJev at 27B parameters and 43ms. All Apache 2.0 except the multilingual OpenJev, which is CC BY-NC. Named use cases from the release: request routing, content moderation, and agent step checking or selection.

The connection to this week's earlier cards is worth naming. Armin Ronacher's `ins_ronacher-codemode-harness-bash-limit` (October 6) described harness-side operations that bash cannot invoke. Michael Lynch's `ins_lynch-agent-layer-bottleneck` (October 9) described agents running parallelizable decisions serially. Decision models fit both problems: they are lightweight enough to call from a harness-side classification step, and they return in a single pass without the serial token-generation overhead Lynch described.
