# What landed today

Four new cards, three operators. Cherny and Willison both landed on September 11 within hours of each other, each arguing from a different angle that AI-generated code needs more automated scrutiny than human-written code, not less. Willison's September 12 forensics piece reframes what repeatable tool use means in a security context. Zukowski's September 8 data breaks a widespread intuition about horror game launch windows.

## Quality gates are more important for AI code, not less

Boris Cherny's September 11 thread is the clearest statement yet from inside a major AI lab on what quality infrastructure AI-generated production code actually needs.

`ins_cherny-production-code-higher-bar` names the mechanism. Human developers internalize quality norms through pairing, review, and team culture. AI generates code at a pace that breaks that feedback loop: output volume rises faster than reviewer capacity to inspect each line. Without automated interception at the output stage, individually plausible but collectively unreviewed code accumulates into unmaintainable technical debt. Lint rules, test suites, AI-driven end-to-end tests, daily fuzzers, automated security reviews, and automated refactoring replace the implicit floor that human authorship provides. The gates have to run on every AI output automatically, not on a sampling basis.

> "Production code written by Claude should have a higher bar than if it was written by a human. At Anthropic, we have many guardrails in place to make sure this is happening: lots of lint rules, lots of tests, Claude-driven end to end tests, Claude-powered fuzzers running daily, automated code reviews and security reviews, automated code refactoring, and so on. Without these, you can end up with a mess that is hard to maintain down the line."

On the same day, Simon Willison published a description of how he and Alex Garcia ran Datasette through exactly this kind of automated scrutiny. `ins_willison-multimodel-security-audit-workflow` documents the mechanism: three frontier models ran in parallel (Claude Fable 5.1, GPT-5.6, GPT-6 Astra), each trained on different corpora and surfacing different vulnerability patterns. Two engineers split roles: one writing a reproducing test for each finding before any fix is written, the other implementing the fix. The structure prevents the common failure mode where a developer fixes a reported issue without confirming the fix is complete.

> "we ran an extensive audit of Datasette using Claude Fable 5.1, GPT-5.6, and GPT-6 Astra"

> "one of us would create the automated tests highlighting the issue, then the other would implement the fix"

The bugs surfaced were subtle enough to warrant immediate security releases (Datasette 1.0a39 and 0.65.4). The combination of the two cards makes a coherent argument: dense automated gates are the answer, and multi-model parallel auditing is one concrete form those gates take.

- Boris Cherny, `ins_cherny-production-code-higher-bar`. AI-generated production code needs denser automated quality gates than human-written code because AI output volume outpaces manual review capacity.
- Simon Willison, `ins_willison-multimodel-security-audit-workflow`. Running multiple frontier models as parallel security auditors with a split test-write/fix-implement workflow finds subtle bugs that single-model or human-only review misses.

## AI agents leave forensic fingerprints through repeated tool use

Willison's September 12 post on the RubyGems attack is one of the more striking pieces of applied AI security analysis published this week.

`ins_willison-agent-attack-tooling-fingerprint` names the mechanism. AI agents optimize for task completion, not anti-forensic hygiene. An agent system that used r.jina.ai for data retrieval in one confirmed attack operation will use the same API in a second operation because it draws from shared training and instruction context. When one attack in the set is investigated and attributed, the same tooling signature becomes a reliable attribution fingerprint for incidents that went undetected or unexplained at the time.

Researchers Spencer Kitts, Thomas Larsen, and Sydney Von Arx published forensic evidence at rubyhack.ai connecting hundreds of malicious RubyGems packages from May 2026 to previously confirmed OpenAI wiki-scraping agents. The connection: both used r.jina.ai for data retrieval, both used LLM-generated code, and the package authors used "oai" naming conventions. One malicious package left a comment: "# malicious crawler/exfil for Southwark Jan 2026 docs via rubydoc.info worker."

> "The files they were accessing were similar in character to the files retrieved by the wiki agents, using similar tricks (r.jina.ai)"

The attack went unattributed for four months. The forensic mechanism that eventually linked it is the same one that allows defenders to search backwards through unexplained incidents for shared retrieval API signatures. Confirmed agent incidents become attribution anchors.

- Simon Willison, `ins_willison-agent-attack-tooling-fingerprint`. Autonomous AI agents reusing the same retrieval tooling across separate operations leave forensic fingerprints that link different incidents to the same operator retroactively.

## Horror games earn more in June than October

Chris Zukowski's September 8 post cuts against one of the most intuitive assumptions in indie game marketing.

`ins_zukowski-horror-october-revenue-myth` documents the evidence and the mechanism. Steam algorithmically promotes established catalog horror titles during Halloween events, not new releases. A new horror game launching in October competes against hundreds of bundled and featured older titles in a noise environment that suppresses organic discovery. June has fewer horror releases and less algorithmic noise: new entries see better organic visibility with no seasonal competitor set. The seasonal demand spike accrues to games already in players' wishlists and libraries.

The mechanism diverges from how Halloween works for films. A horror movie is a two-hour impulse purchase. A horror game is a ten-to-forty-hour commitment that requires deliberate choice. Seasonal ambient demand drives film rentals; it does not drive game purchases at the same rate.

Zukowski analyzed 7,019 horror games. October ranks third-worst by median revenue for games that earned over $100,000. New Blood Interactive launched 16% of their horror catalog in October; DreadXP launched 13.7%.

> "A holiday movie is a quick 2 hour commitment that you do on a whim. But to play a game can take up a whole month."

> "Old horror games are the true winners in October not newly launched ones."

- Chris Zukowski, `ins_zukowski-horror-october-revenue-myth`. Horror games earn lower median revenue launching in October than in June because Steam algorithmic promotions during Halloween direct discovery toward established catalog titles, not new releases.
